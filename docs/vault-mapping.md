# Vault Mapping

Crew подстраивается под существующую структуру папок — переименовывать ничего не нужно.

## Как это работает

Во время онбординга Архитектор сканирует ваше хранилище и уточняет неоднозначные папки. Затем он создаёт `Meta/vault-map.md` — файл, который привязывает логические роли к именам ваших реальных папок:

```yaml
---
inbox: 00-Inbox
projects: 01-Projects
areas: 02-Areas
resources: 03-Resources
archive: 04-Archive
people: 05-People
meetings: 06-Meetings
daily: 07-Daily
templates: Templates
meta: Meta
moc: MOC
---
```

Каждый агент и навык читают этот файл при выполнении по фиксированному пути `Meta/vault-map.md` и подставляют vault-role токены в реальные пути до того, как что-то сделать. Подставляются только 11 токенов из списка ниже — остальные `{{...}}` (например, `{{date}}`, `{{Name}}`) считаются шаблонными плейсхолдерами и не трогаются.

## Кастомизация

Просто отредактируйте `Meta/vault-map.md` напрямую. Например, если ваш инбокс называется `Inbox/`:

```yaml
inbox: Inbox
```

Изменения вступают в силу сразу — перезапуск не нужен.

## Доступные токены

| Токен | По умолчанию | Назначение |
|-------|--------------|------------|
| `{{inbox}}` | `00-Inbox` | Сюда падают новые заметки |
| `{{projects}}` | `01-Projects` | Активные проекты |
| `{{areas}}` | `02-Areas` | Зоны жизни (Работа, Здоровье и т.д.) |
| `{{resources}}` | `03-Resources` | Справочные материалы |
| `{{archive}}` | `04-Archive` | Завершённые или исторические заметки |
| `{{people}}` | `05-People` | Заметки про людей |
| `{{meetings}}` | `06-Meetings` | Заметки встреч |
| `{{daily}}` | `07-Daily` | Ежедневные заметки |
| `{{templates}}` | `Templates` | Шаблоны заметок |
| `{{meta}}` | `Meta` | Конфиг-файлы Crew |
| `{{moc}}` | `MOC` | Maps of Content |

## Если vault-map.md отсутствует

Каждый агент откатывается на дефолты выше и предупреждает об этом один раз. Существующие пользователи никак не страдают — Crew работает ровно как раньше, пока вы не запустите онбординг.
